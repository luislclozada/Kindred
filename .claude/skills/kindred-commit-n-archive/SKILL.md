# kindred-commit-n-archive = openspec-sync + openspec-archive + commit + graph resync

A thin orchestrator. **Never copy content from the openspec skills** — delegate via the
**Skill tool**; they are regenerated by the openspec CLI and must stay upgradable.
Archiving is the moment change knowledge becomes authoritative truth (`authority:
CURRENT` main specs) — the graph must record that moment. The commit sits BETWEEN the
archive and the resync on purpose: `ingest resync` diffs from the last ingested
**commit**, so the archive move and main-spec rewrites must be committed before the
resync can see them.

## Steps

### 1. Delegate sync + archive

Invoke the `openspec-archive-change` skill (Skill tool) with the user's arguments. It
already handles change selection, completion warnings, the delta-spec sync assessment,
and delegating to `openspec-sync-specs` — preserve ALL of its prompts and safeguards
(never auto-select a change, never skip its confirmation questions).

If the change shipped a user-visible feature, add its entry to `docs/FEATURES.md`
(`- [Title](features/<name>/) (YYYY-MM-DD) — one sentence`) and a short
`docs/features/<name>/README.md` before the commit, so the graph gets a Feature node.

### 2. Commit (after a successful archive) — the user's call

Commits are user-owned. Do not commit without an explicit yes in this turn, and never push.

1. `git status` — list what will go in: the archive move
   (`openspec/changes/archive/YYYY-MM-DD-<name>/`), the rewritten main specs, the spine
   edit, the implementation files and migrations belonging to this change, and any docs
   from step 1.
2. **Scope guard**: if the tree carries work unrelated to this change, stage explicit paths
   only — never sweep unrelated work into the archive commit.
3. Propose a commit message (what the change does, in one line, plus a short body) and
   **ask the user to approve or edit it**. Only then:

   ```bash
   git add <explicit paths>
   git commit -m "<approved message>"
   ```

If the user declines the commit, stop here: say the resync will no-op until the commit
exists, and list step 3 as a follow-up.

### 3. Resync the graph (after the commit lands)

```bash
dotnet run --project tools/Kindred.KnowledgeGraph -- ingest resync
dotnet run --project tools/Kindred.KnowledgeGraph -- ingest embed
```

Resync is git-diff scoped and handles both effects of archiving: the change directory
moved to `openspec/changes/archive/YYYY-MM-DD-<name>/` (old paths tombstoned, archive
paths re-ingested) and the main specs were rewritten (re-ingested as current authority —
an `IN_FLIGHT` spec becomes `CURRENT`).

**Verify post-conditions** from the resync summary / `knowledge-graph/last-validation-report.json`:
- no UNBOUND sources (the archived change binds via the same alias; extend
  `knowledge-graph/capabilities.yaml` and re-run if not);
- the tombstone line shows the moved change paths were cleaned up;
- no new rejections pointing at the freshly synced specs.

Then **prove the graph remembers**: re-run the existence query that the proposal started
with (`q query "<the feature>"`). It must now come back as shipped — a `CURRENT` spec, the
archived change, and the services/events it added — where before the change it found nothing.

Report what changed in the graph (nodes/edges written, tombstoned counts) as part of the
archive summary.

### 4. Offer Tier C enrichment (optional, NEVER silent)

The synced specs may carry relationship claims the deterministic tiers can't see
(dependencies described in prose). Offer — do not auto-run — an extraction pass: you Read
the new/updated spec files, emit candidate edges per the `kg` skill's Tier C recipe
(verbatim quote + sourceFile, both endpoints already in the graph), then:

```bash
dotnet run --project tools/Kindred.KnowledgeGraph -- ingest import-edges --file <json>
```

Everything lands as `PROPOSED` for `review list` / `review approve` — say that when
offering.

## If Neo4j is down

Complete the sync + archive + commit steps normally (archiving is never blocked on
infrastructure), then say the graph resync was skipped and list steps 3–4 as follow-ups
to run once the store is up:

```bash
docker compose -f docker-compose.dev.yml --profile kg up -d neo4j
```
