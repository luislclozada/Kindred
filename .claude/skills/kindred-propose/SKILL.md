# kindred-propose = KG gate + openspec-propose + spine registration

A thin orchestrator. **Never copy content from `openspec-propose`** — delegate to it via
the **Skill tool**; it is regenerated by the openspec CLI and must stay upgradable.

## Steps

### 1. Existence + duplicate gate (BEFORE any change folder exists)

```bash
dotnet run --project tools/Kindred.KnowledgeGraph -- q query "<requested work>"
```

(or MCP `kg_query`.) **Write the query in Spanish**, whatever language the request came in —
the graph's text is Spanish and a question in another language matches it weakly, and a weak
match is how an existing surface gets missed. Use the glossary in `CLAUDE.md` ("Language"), e.g.
`"formación de grupos de estudio por disponibilidad"`.

If the idea resembles an existing surface, also run
`q detect-duplicates`. Heed a `[knowledge-graph] STALE:` warning: `ingest resync` +
`ingest embed`, re-query — gating on a stale graph defeats the gate.

- **Overlap found** (an existing capability/feature/spec or an in-flight change
  substantially covers the request): present the overlap WITH its `sourceFile@commit`
  citations and make the user choose — **extend the existing surface** (often a smaller
  change against the existing spec) or **justify the new one** (the justification goes
  in the proposal's Why). Do not create anything until they choose.
- **No overlap**: say plainly that the graph has no accepted evidence of existing
  coverage, and proceed.

Also take the **blast radius** of what the change will touch
(`q query "<surface it modifies>" --kind blast`) and carry it into the proposal: which
services, which integration events, which module bridges. It decides how tasks.md is cut
into sections, and `kindred-apply` splits teams along those sections.

### 2. Delegate

Invoke the `openspec-propose` skill (Skill tool) with the user's original arguments.
The artifacts are written in **Mexican Spanish** — proposal, design, tasks and spec prose —
keeping the OpenSpec structure and the keyword `MUST` in English (`openspec/config.yaml`,
"Language"). They are embedded into the graph, and the graph is queried in Spanish.
Cite the gate's findings in the proposal (the config rules require it): existing
coverage found or "none found", and the extend-vs-new justification if there was overlap.

### 3. Register the change in the capability spine (the "grow" step)

After the change folder exists at `openspec/changes/<name>/`:

1. Hand-edit `knowledge-graph/capabilities.yaml`:
   - Usually: add `<name>` to the `aliases` of the capability the change belongs to.
   - Only when the change introduces a genuinely new capability: mint a new spine entry
     (id + name + description + module + aliases) — the spine file is the ONLY place
     capability ids are minted, and a new mint should be said out loud in your output.
   - A new cross-module seam (a new integration event between modules) is declared under
     `bridges:`.
2. Re-ingest and confirm the change binds:

   ```bash
   dotnet run --project tools/Kindred.KnowledgeGraph -- ingest run
   dotnet run --project tools/Kindred.KnowledgeGraph -- ingest embed
   ```

   Check the summary (and `knowledge-graph/last-validation-report.json`): the new change
   must NOT appear as UNBOUND, and neither may any spec it introduces. If one does, the
   alias didn't match — fix the alias and re-run.
3. Prove it: re-run the step 1 query. The change must now come back (a `Change` node with
   its task progress, and an `IN_FLIGHT` spec for anything brand new). In-flight work must
   be visible to existence queries from day one; that is the whole point.

`ingest run` reads the working tree, so the new change is in the graph before it is
committed. Do not commit — commits are the user's call.

## If Neo4j is down

Say so, offer the start command, delegate to `openspec-propose` anyway (spec work is
never blocked on infrastructure), and end your output with an explicit follow-up list of
the skipped KG steps: existence/duplicate gate, spine alias, `ingest run` + UNBOUND check.

```bash
docker compose -f docker-compose.dev.yml --profile kg up -d neo4j
```
