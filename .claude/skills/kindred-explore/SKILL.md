# kindred-explore = knowledge graph + openspec-explore

A thin orchestrator. Do the KG grounding below, then delegate to the generated
`openspec-explore` skill via the **Skill tool**, passing the user's arguments through
unchanged. **Never copy content from `openspec-explore`** — it is regenerated by the
openspec CLI and must stay upgradable.

## Steps

1. **Ground in the graph** (skip gracefully if unavailable — see below). For the topic the
   user brought, run:

   ```bash
   dotnet run --project tools/Kindred.KnowledgeGraph -- q query "<topic>"
   ```

   (or the MCP tool `kg_query` if the `kg` server is connected — same engine.)

   **Write the query in Spanish**, whatever language the user used: the graph's text is
   Spanish, and a question in another language matches it weakly. Use the glossary in
   `CLAUDE.md` ("Language").

   Synthesize what came back per the `kg` skill's quality contract: cite
   `sourceFile@commit`, never present `[DISPUTED]` as true, `[PROPOSED]` only as an
   unconfirmed candidate, specs beat docs, an `IN_FLIGHT` spec is not built yet, both
   endpoints of a `BRIDGES` edge are in a blast radius.

   If the output starts with a `[knowledge-graph] STALE:` warning, run
   `ingest resync` then `ingest embed` first, then re-query — explore on current
   state, not last week's.

2. **Delegate**: invoke the `openspec-explore` skill (Skill tool) with the user's
   original arguments. Carry the cited findings into the exploration — they are the
   "current state" half of the conversation: what already exists, who owns it, what
   depends on it, what is in flight, what's deprecated (`SUPERSEDED_BY`).

3. During exploration, reach back for the graph freely (`q query --kind blast` when
   discussing changing something, `q detect-duplicates` when an idea smells like an
   existing surface). The graph is advisory context — Read the cited files for
   behavioral detail before relying on them.

## If Neo4j is down

Say so, offer the start command, and continue with the delegation — never block
thinking time on infrastructure:

```bash
docker compose -f docker-compose.dev.yml --profile kg up -d neo4j
```

State explicitly in the exploration that KG grounding was skipped, so stale-doc claims
are treated with extra suspicion.
